# Decisions

설계 결정과 그 이유. 문제가 발생해서 바꾼 것은 `troubleshooting.md`, 처음부터 그렇게 설계한 것은 여기에 적는다.

| ID | 결정 | 이유 | 대안과 기각 이유 |
|---|---|---|---|
| D-01 | 새 프로젝트로 시작 (Next.js + TS) | 레포가 비어 있었음 (phase1-analysis.md) | — |
| D-02 | **계산 = 코드, 설명 = AI** | 시간 계산을 LLM에 맡기면 검증할 수 없고 결과가 매번 달라진다. 코드는 테스트할 수 있다 | LLM에게 전체 데이터를 주고 계획 생성 → 시각 오류를 막을 방법이 사후 검증뿐 |
| D-03 | 날짜 `YYYY-MM-DD`, 시간 `HH:mm` **문자열**로 저장 | `Date`/UTC ISO로 저장하면 KST 자정 근처에서 날짜가 하루 밀릴 수 있다. 날짜 차이는 `Date.UTC` 기반 epoch day로 계산 | Date 객체 + 타임존 라이브러리 → 의존성 증가 |
| D-04 | 자연어 파싱에서 LLM은 날짜 **표현**만 반환 (`dateType`, `weekday`, `weekOffset`…) | "다음주 수요일" 같은 계산을 코드로 고정하면 AI/규칙 파서가 같은 결과를 낸다 | LLM이 `YYYY-MM-DD` 반환 → 요일 계산 오류를 검증하기 어렵다 |
| D-05 | AI 응답을 **필드 단위**로 검증·폐기 | 요약 한 문장이 틀렸다고 전체 AI 결과를 버리면 AI가 거의 쓰이지 않는다 | 전체 거부 후 재시도 → 지연 2배 |
| D-06 | 하루 과제 배치 상한 6시간 | 수업·약속이 있는 날 현실적인 상한 | 상한 없음 → 빈 시간을 전부 과제로 채움 |
| D-07 | AI 브리핑 캐시 키 = **원천 데이터 해시 + 날짜**, 60분 TTL | AI 컨텍스트엔 매 분 바뀌는 "남은 시간"이 들어 있어, 그걸로 키를 만들면 매 분 재호출된다 | 매 분 호출 → 비용·지연 |
| D-08 | "지금 뭐 하지?"는 **버튼을 눌렀을 때만** AI 호출 | 대표 기능을 사용자가 능동적으로 쓰게 하고, 호출 수를 줄인다. 결정은 누르는 즉시 코드가 보여줌 | 자동 호출 → 매번 비용 |
| D-09 | 로그인 없음, localStorage + `StorageAdapter` | 요구사항("불필요한 로그인 금지"). 어댑터만 바꾸면 서버 DB로 이전 가능 | Supabase 등 → MVP 범위 초과 |
| D-10 | 이동시간은 규칙 기반 추정 + 사용자 입력 우선, UI에 항상 "추정" 표시 | 지도 API 없이 동작해야 하고, 가짜로 정확한 척하면 안 된다 | 고정값 → 캠퍼스 내 이동과 외부 이동을 구분 못 함 |
| D-11 | 미구현 연동(날씨, 캘린더, 알림)은 인터페이스만, UI 노출 없음 | "구현되지 않은 기능을 UI에 가짜로 표시하지 않는다" | — |
| D-12 | 모든 AI 결과에 `AI` / `규칙 기반` 배지 | 사용자가 무엇이 AI인지 알 수 있어야 하고, 발표에서 폴백을 투명하게 보여줄 수 있다 | — |
| D-13 | 데모 시간 고정(sessionStorage) | 발표 시각과 무관하게 "16:10 풋살 전" 시나리오를 재현 | 시스템 시간 변경 → 번거롭고 위험 |
| D-14 | effort `low` | 입력이 이미 계산된 요약이라 깊은 추론이 필요 없고, Today 로딩 체감에 직접 영향 | 기본(high) → 지연 증가 |
| D-15 | 오전/오후 없는 1~7시는 오후로 해석하고 사용자에게 알림 | 대학생 일정에서 "6시 풋살"은 대부분 저녁. 틀릴 수 있으므로 미리보기에서 확인하게 함 | 매번 되묻기 → 입력 흐름이 끊김 |
