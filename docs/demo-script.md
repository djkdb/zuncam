# 데모 스크립트 & 발표 구성

## 준비

1. `npm run build && npm start` (또는 `npm run dev`)
2. AI 연결: `.env.local`에 `ANTHROPIC_API_KEY`. 키가 없으면 규칙 기반으로 동일한 흐름이 동작한다 (배지로 구분됨)
3. 브라우저 새 창 → 설정 → 데이터 "전체 삭제" (깨끗한 상태) → Today → **데모 시나리오 (16:10 고정)**
   - 오늘 날짜 기준 샘플: 수업 2개(10시 운영체제, 14시 컴퓨터 네트워크), 오늘 23:59 마감 자료구조 과제(90분), 18시 CLASS FC 풋살(이동 35분)
   - 상단 노란 띠: "데모 시간 16:10"

## 2~3분 대표 시연

| 단계 | 행동 | 보여줄 포인트 |
|---|---|---|
| 1 | 우측 상단 **자연어로 추가** → "금요일 6시에 친구들이랑 풋살 있어" → 해석하기 | 일정으로 인식, 금요일 날짜 계산, 18:00(오전/오후 모호 안내), 카테고리 운동. 저장 전 수정 가능. `AI`/`규칙 기반` 배지 |
| 2 | 다시 입력 → "자료구조 과제 다음주 수요일까지고 2시간 정도 걸릴 것 같아" → **과제**로 인식 → 추가 | 날짜 표현은 AI, 날짜 계산은 코드. 마감 시각 없음 → 23:59 기본값 안내 |
| 3 | Today 화면 | 5초 요약 4칸 → 오늘의 우선순위(점수 근거 펼치기) → AI Recommendation |
| 4 | **지금 뭐 하지?** 클릭 | "지금은 자료구조 과제를 시작" · 16:10 → 17:20 · 1시간 10분 · 17:20 풋살 출발 |
| 5 | 자연어로 "오늘 저녁 7시에 친구 약속 있어" | 저장 전 모달에서 **"'CLASS FC 풋살'과 '친구 약속'이 60분 겹칩니다"** → 저장 → Today 충돌 카드 + AI 해결 제안 |

> ⚠ 5단계 충돌은 반드시 **현재(데모) 시각 이후**로 만든다. 이미 지난 충돌은 Today에서 숨겨진다 (troubleshooting TS-04).

추가로 보여줄 수 있는 것: 우선순위 1번 과제의 **완료** 버튼 → 목록·계획에서 즉시 빠지고 다음 과제가 올라옴 (이미 완료한 작업을 다시 추천하지 않음).

## 중간 발표 (5~7분) 구성안 — 평가: 독창성 30 / 문제 정의 20 / AI 활용 계획 40 / 발표 10

1. 문제 (1분) — "그래서 지금 뭐 해야 하지?" 흩어진 정보를 머릿속에서 합치는 비용. `problem-definition.md`
2. 차별점 (1분) — 캘린더가 아니라 Today. 기존 앱 비교 표
3. AI 활용 설계 (3분) — 가장 비중이 큰 항목
   - `Raw Data → Campus Context → Priority Engine → LLM → 검증` 다이어그램 (`architecture.md`)
   - "계산은 코드, 설명은 AI" — 왜? (D-02)
   - AI 기능 5개와 각각의 입력/출력 스키마/검증 (`ai-workflow.md`)
   - 실패해도 동작하는 폴백 표
4. 데모 미리보기 (1분)
5. 향후 계획 (30초)

## 최종 발표 (7~10분) 구성안 — 평가: 프롬프팅·트러블슈팅 40 / 완성도 30 / 경험·성장 20 / 시연 10

1. 한 문장 소개 + 시연 (3분) — 위 5단계
2. 프롬프팅 (2분) — `prompt-history.md`의 실제 변경 이력 (실제 모델로 측정한 전/후 issues 수)
3. 트러블슈팅 (2분) — `troubleshooting.md`에서 2~3개: TS-01(비현실적 계획), TS-03(타임아웃 곱셈), 실제 모델 측정 중 발견한 것
4. 검증 설계 (1분) — 목 서버로 환각 시각을 주입해도 화면에는 계산된 시각만 남는 것을 시연 ("AI · 검증 2건 보정" 배지)
5. 배운 점 (1분)
